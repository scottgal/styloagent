# Styloagent v1.13.4

v1.13.4 fixes terminal state loss and wheel routing that could corrupt OpenCode's display when scrolling after a pane was reattached.

## Changes

- Keep one bounded VT state per running PTY, starting before its output reader. Replacing a dock view uses that state instead of reconstructing the terminal from a truncated 256 KiB raw tail. Alternate-screen, mouse, color and parser state survive, including output received while the pane is hidden.
- Share the underlying terminal state through the OpenCode runtime wrapper. Keep native rendering on its fixed screen grid and disable the outer scrollbar there.
- Send wheel events through the terminal's negotiated mouse protocol at the pointer's cell. Accumulate fractional trackpad deltas, preserve Ctrl+wheel zoom and keep ordinary transcript scrollback working.
- Preserve tail-follow state while resizing the render surface.

## Verification

- The Release regression suite passed **1,195 tests**, with eight opt-in integration tests skipped: Core 616, Git 26, App 393, UI 160.
- Four opt-in UI/process tests passed separately against real OpenCode **2.0.25** and POSIX PTYs on macOS arm64. The long OpenCode probe overflows the replay cap, replaces the pane, sends actual window mouse-wheel events, reaches earlier history, produces more output and returns to the latest result. The outer viewport stays fixed.
- A real shell emits over 500 KiB before any terminal view attaches. Its capped raw tail no longer contains startup commands, but the attached view preserves the original alternate-screen header and final redraw.
- Deterministic regressions cover lost startup modes after replay truncation, hidden redraws, exact mouse coordinates and direction, fractional trackpad input, and fixed line heights while scrolling colored diff output. The mode-loss and missing-wheel tests failed before the fixes.
- [Captured real OpenCode scroll view](../evidence/opencode-scroll-1.13.4.png).

The current running application must be restarted after updating to use this fix. The live verification used isolated temporary projects and did not interrupt the user's running fleet. OpenCode is installed separately; no provider generation or API credits are needed by these four UI/process checks.
